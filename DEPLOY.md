## 5. Post-deploy smoke test

```powershell
# 5.1 Set the deploy URL (paste the URL from step 4.1; no trailing slash)
$URL = "https://squad-night-<hash>-vt01nft.vercel.app"

# 5.2 Pages: all three must return 200
(Invoke-WebRequest -Uri "$URL/").StatusCode
(Invoke-WebRequest -Uri "$URL/night").StatusCode
(Invoke-WebRequest -Uri "$URL/night/result").StatusCode
# PASS: 200 for each

# 5.3 POST /api/negotiate with the sample squad (two members, six favorites)
$body = @'
{
  "members": [
    { "name": "Ari", "picks": ["Inception", "City of God", "SZA"] },
    { "name": "Bo",  "picks": ["Burna Boy", "The Bear", "ramen"] }
  ],
  "city": "New York"
}
'@
$result = Invoke-RestMethod -Method Post -Uri "$URL/api/negotiate" -ContentType "application/json" -Body $body
$result | ConvertTo-Json -Depth 6

# 5.4 PASS criteria — check in the output above:
#   HTTP status 200 (no error field)
#   $result.movie.title        — non-empty, real film title, NOT one of the six picks
#   $result.restaurant.title   — non-empty, real venue/food title, NOT one of the six picks
#   $result.movie.affinity -gt 0.3
#   $result.restaurant.affinity -gt 0.3
#   $result.meta.groundedFavorites -eq 6   (all six favorites grounded via Qloo /search)
#   $result.grounding       — two members, each with resolved entries
#   $result.negotiation     — 3 lines, each citing a losing candidate's affinity number
#   $result.counterfactual  — present (no-taste-data side-by-side)
#
# 5.5 Regression check: a request without members must fail loudly, not fake a result
$err = Invoke-WebRequest -Method Post -Uri "$URL/api/negotiate" -ContentType "application/json" -Body '{}' -SkipHttpErrorCheck
$err.StatusCode
# PASS: 400 with a { "error": ... } body

# 5.6 Use the browser once: open $URL/night, build the same squad, share the result URL,
# and reload — the squad survives the refresh (URL-encoded state).
```

## 8. Known constraints

- **Server-only secrets.** `QLOO_API_KEY` / `GEMINI_API_KEY` are read exclusively in `src/app/api/negotiate/route.ts` (`export const runtime`-agnostic server scope: the App Router route module). They must be added in Vercel **Production** only via step 3; they are never referenced from client components, and browser bundles must stay clean (section 1.5 proves this per build).
- **No .env files committed.** `.gitignore` excludes `.env*` and `.vercel` (verified: `git ls-files | Select-String -Pattern '\.env'` returns nothing). The secrets never enter the repo or the build output.
- **No database on Vercel.** Squad state is base64url-encoded in the shareable result URL (`src/lib/squad/codec.ts`); the API is stateless — a POST to `/api/negotiate` plus a GET readback is the entire persistence surface. Nothing server-side to provision.
- **`maxDuration` honored on Hobby.** Verified in `src/app/api/negotiate/route.ts` line 11: `export const maxDuration = 60;` is present. Per https://vercel.com/docs/functions/configuring-functions/duration (updated 2026-08-24), with fluid compute the Hobby plan default AND maximum are **300 s** — the older 10 s / 60 s Hobby caps are outdated. Vercel therefore honors 60 s, and the ~10–20 s negotiation fits comfortably: NO change to the route is needed for this deploy. (If Vercel ever reported a smaller effective cap, do not ship a clamped value — reduce the wait instead, e.g. tighten the LLM call timeout in `src/lib/agent/llm.ts`.) Keep only `maxDuration` as a route config export; other exports (e.g. `runtime`) were already removed for Next 16 `cacheComponents` compatibility.
- **First deploy cold start.** The first POST to `/api/negotiate` after deploy/cold start can add a few seconds on top of the ~10–20 s negotiation; still within 60 s. Re-run smoke test 5.3 once more after the first call if it timed out spuriously.
- **Env changes require redeploy** to take effect in production: `vercel --prod --yes` again after any `vercel env add`.
